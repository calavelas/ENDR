Architecture (how a robot maps to the real platform)

A robot is just a normal ENDR service whose behaviour is 100% env-driven, running a shared prebuilt image:

portal /create (robot) edit calibration (fix) │ image=endr-robot │ overrides.env { HUMOR… } │ env={ROBOT_NAME,HUMOR,…} ▼ ▼ services.yaml (single source of truth) services.yaml entry ──PR──▶ reconcile (engine services-check) │ renders services/<name>/chart + KUBE ArgoCD app │ env → deployment.yaml container env ▼ ArgoCD ──▶ pod runs calavelas/endr-robot reads HUMOR/HONESTY/TRUST → ONLINE (sum>0) | MALFUNCTION (all 0)
  • The robot app (apps/robot/app.py, image calavelas/endr-robot via robot-build.yml) already renders ONLINE/MALFUNCTION from env + exposes /healthz and /api/status. ✅ exists.
  • Calibration lives in services.yaml overrides.env (not Helm values.yaml — the gitops template injects env straight into the generated deployment.yaml). So both create and fix are services.yaml-only PRs, reusing the existing auto-merge policy in reconcile-pr.yml.
  • Break = create with empty/zero calibration → MALFUNCTION. Fix = edit env via PR → ONLINE. Destroy = remove the entry → ArgoCD prunes.
  • Backend CreateServiceRequest already accepts image + env — no API change needed for create.

TARS / CASE guidance assistant. The shared robot image gained a scripted guidance brain: apps/robot/journey.py + GET/POST /api/guide (stdlib only, permissive CORS). It returns a context-aware tour (welcome→create→deploy→catalog→history→done + help/malfunction) whose vocabulary follows the request's narrative mode and whose voice follows the pod's HUMOR/HONESTY/TRUST. Two deployments — tars (humor 90, witty) and case (humor 30 / honesty 95, terse) — added to services.yaml with charts under services/{tars,case}/chart and ArgoCD apps in KUBE/clusters/mac/lab/services/. The portal mounts a floating widget (components/assistant/*) that proxies via /api/assistant to the right pod (default CASE in IDP, TARS in Interstellar; switching persona switches pod — the live "one image, two deployments" proof), with a baked-in cached-guidance fallback so it works cluster-free. Live-demo prereq: rebuild/push endr-robot for /api/guide; optionally set ASSISTANT_TARS_URL/ASSISTANT_CASE_URL on the portal.
